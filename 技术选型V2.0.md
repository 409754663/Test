## 二、多租户与跨站协作架构

系统采用**"租户为基座，四种机制各司其职"**的架构模式，以应对两极分化的市场：

- **极小型客户**：3-5人团队运营一个小型搅拌站，使用单租户模式，无跨站概念
- **集团大客户**：多个站点需要集中调度、集采、报表审阅、信息共享

### 2.1 四种机制总览

| 机制                            | 业务场景               | 数据流向     | 权限类型  | 适用客户 |
| :------------------------------ | :--------------------- | :----------- | :-------- | :------- |
| **租户（Tenant）**              | 独立站点日常经营       | 站内闭环     | 完整操作  | 所有客户 |
| **组织层级（Parent-Child）**    | 集团报表审阅           | 单向向上汇总 | 只读穿透  | 集团客户 |
| **协作域（Collaboration Hub）** | 跨站集中调度、集中采购 | 双向协同     | 操作共享  | 集团客户 |
| **公告与知识库**                | 集团信息下发、共享资料 | 单向向下广播 | 发布-订阅 | 集团客户 |

### 2.2 租户设计（Tenant）

**适用场景**：所有搅拌站都必须是一个租户。极小型客户只有一个租户，集团客户每个搅拌站各自是一个租户。

**设计要点**：

- 所有业务表包含 `TenantId` 字段，EF Core 全局查询筛选器自动注入 `WHERE TenantId = @currentTenantId`
- 通过 `Sys_TenantLicenses` 表管理功能包购买与开通
- 极小型客户登录后只看到自己的站点，不显示任何跨站菜单
- 大客户根据已购许可证包展示对应功能

**数据库核心表**：

### 2.3 组织层级设计（Parent-Child Hierarchy）

**适用场景**：集团财务总监查看所有子公司应收应付汇总报表，集团技术总工审阅各站点配合比使用情况，集团总经理查看各站点生产日报。

**为什么独立于协作域**：报表审阅是上下级关系的只读查看，协作域是对等关系的双向操作，权限模型完全不同，必须分离。

**设计要点**：

- 利用 `Sys_Tenants.ParentTenantId` 建立父子关系
- 通过 `Sys_ReportReviewPermissions` 表精细化控制审阅权限
- 可限制某人只能看"财务报表"而不能看"生产配比"
- 子公司日常操作不受集团查看影响

**数据库核心表**：

sql

```
-- 报表审阅权限表
CREATE TABLE Sys_ReportReviewPermissions (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    UserId          INT NOT NULL,
    ParentTenantId  INT NOT NULL,                     -- 集团ID
    ChildTenantId   INT NOT NULL,                     -- 可审阅的子公司ID
    ReviewScope     VARCHAR(50) NOT NULL,             -- 'All' | 'Finance' | 'Production' | 'Quality'
    IsActive        BIT NOT NULL DEFAULT 1,
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CreatedBy       INT NOT NULL,
    INDEX IX_ReportReview_User (UserId),
    UNIQUE INDEX UQ_ReportReview (UserId, ParentTenantId, ChildTenantId, ReviewScope)
);
```



**JWT Token 扩展**：

**后端查询实现**：

csharp

```
// 集团报表服务
public async Task<GroupFinanceReport> GetGroupFinanceReport(int userId, int parentTenantId)
{
    var childTenantIds = await _dbContext.Sys_ReportReviewPermissions
        .Where(p => p.UserId == userId && p.ParentTenantId == parentTenantId 
                 && p.ReviewScope == "Finance" && p.IsActive)
        .Select(p => p.ChildTenantId)
        .ToListAsync();
    
    return await _dbContext.FinanceRecords
        .IgnoreQueryFilters()  // 临时禁用单租户过滤
        .Where(r => childTenantIds.Contains(r.TenantId))
        .GroupBy(r => r.TenantId)
        .Select(g => new TenantFinanceSummary { ... })
        .ToListAsync();
}
```



### 2.4 协作域设计（Collaboration Hub）

**适用场景**：

- **集中调度域**：京西片区下A、B、C三个站成立集中调度中心，调度员可同时查看和操作三个站的任务和车辆
- **集采中枢域**：北京地区所有站点统一采购水泥，共享供应商和合同
- **灵活租站**：新租站点加入调度域即纳入统一管理，退租后移除

**为什么独立设计**：协作域是对等成员间的双向操作协同，与组织层级的上下级只读审阅完全不同。一个站点可同时属于多个域。

**数据库核心表**：

sql

```
-- 协作域定义
CREATE TABLE Col_CollaborationHubs (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    HubCode         VARCHAR(30) NOT NULL UNIQUE,
    HubName         NVARCHAR(100) NOT NULL,
    HubType         VARCHAR(30) NOT NULL,             -- 'CentralDispatch' | 'CentralProcurement'
    OwnerTenantId   INT NOT NULL,
    RegionCode      VARCHAR(10) NULL,
    Status          TINYINT NOT NULL DEFAULT 1,
    ConfigJson      NVARCHAR(MAX) NULL,
    TenantId        INT NOT NULL,
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    UpdatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CreatedBy       INT NOT NULL,
    UpdatedBy       INT NOT NULL,
    IsDeleted       BIT NOT NULL DEFAULT 0
);

-- 协作域成员
CREATE TABLE Col_TenantHubMembers (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    TenantId        INT NOT NULL,
    HubId           INT NOT NULL,
    JoinType        VARCHAR(20) NOT NULL DEFAULT 'FullMember', -- 'FullMember' | 'ViewOnly'
    JoinedAt        DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    LeftAt          DATETIME2 NULL,                  -- 退出时间
    IsActive        BIT NOT NULL DEFAULT 1,
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    UpdatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    IsDeleted       BIT NOT NULL DEFAULT 0,
    INDEX IX_TenantHubMembers_HubId (HubId),
    UNIQUE INDEX UQ_TenantHub (TenantId, HubId)
);
```

### 2.5 公告与知识库设计

**适用场景**：集团发布供应商名录更新、施工规范调整、安全培训通知等，所有子公司按需接收和查看。

**为什么独立设计**：一对多广播，内容管理属性（时效性、已读追踪），与协作域的双向协同完全不同。

**数据库核心表**：

sql

```
-- 公告表
CREATE TABLE Info_Announcements (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    PublisherTenantId INT NOT NULL,
    Title           NVARCHAR(200) NOT NULL,
    Content         NVARCHAR(MAX) NULL,
    Category        VARCHAR(50) NOT NULL,             -- 'Notice' | 'Policy' | 'Training' | 'SupplierInfo'
    Priority        TINYINT NOT NULL DEFAULT 0,       -- 0=普通 1=重要 2=紧急
    IsPinned        BIT NOT NULL DEFAULT 0,
    PublishAt       DATETIME2 NOT NULL,
    ExpireAt        DATETIME2 NULL,
    TenantId        INT NOT NULL,
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CreatedBy       INT NOT NULL,
    UpdatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    UpdatedBy       INT NOT NULL,
    IsDeleted       BIT NOT NULL DEFAULT 0
);

-- 公告可见范围
CREATE TABLE Info_AnnouncementTargets (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    AnnouncementId  INT NOT NULL,
    TargetTenantId  INT NOT NULL,
    IsReadRequired  BIT NOT NULL DEFAULT 0,
    INDEX IX_AnnouncementTargets_AnnId (AnnouncementId),
    INDEX IX_AnnouncementTargets_TenantId (TargetTenantId)

-- 已读记录
CREATE TABLE Info_AnnouncementReadLogs (
    Id              INT IDENTITY(1,1) PRIMARY KEY,

    ReadAt          DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),

-- 共享知识库
CREATE TABLE Info_SharedKnowledge (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    PublisherTenantId INT NOT NULL,
    Title           NVARCHAR(200) NOT NULL,
```

## 四、后端技术栈选型

| 选型项           | 推荐方案                                            | 备选方案                | 选型理由                                               |
| :--------------- | :-------------------------------------------------- | :---------------------- | :----------------------------------------------------- |
| **框架**         | **.NET 8**                                          | Java 17 (Spring Boot 3) | 与SQL Server同属微软生态，EF Core集成体验业界最佳      |
| **ORM**          | **EF Core 8** + Dapper                              | -                       | EF Core用于80%常规业务，Dapper用于20%复杂报表SQL       |
| **认证与授权**   | **[ASP.NET](https://asp.net/) Core Identity + JWT** | IdentityServer          | 支持多租户多域权限，Token携带Scope和可访问租户列表     |
| **多租户支持**   | **EF Core全局查询筛选器**                           | 数据库RLS               | ORM层自动注入tenant_id，协作域场景可IgnoreQueryFilters |
| **API文档**      | **Swagger / Swashbuckle**                           | -                       | 自动生成交互式API文档                                  |
| **定时任务**     | **[Quartz.NET](https://quartz.net/)**               | Hangfire                | 支持Cron，满足定时备份、自动报表、库存预警             |
| **消息队列**     | **RabbitMQ** (初期Redis Pub/Sub)                    | Kafka                   | 初期Redis轻量处理消息通知和异步报表                    |
| **租户脚本引擎** | **Jint** (JavaScript引擎)                           | ClearScript             | 与前端的JS技术栈统一，纯C#实现安全可控                 |
| **实时通讯**     | **SignalR**                                         | -                       | WebSocket支持调度中心实时车辆状态、任务提醒            |

## 五、报表与打印方案

### 5.1 报表分层架构

搅拌站ERP的报表需求分为三个层次，每层技术方案不同：

| 层次             | 说明                 | 典型报表                               | 技术方案                       |
| :--------------- | :------------------- | :------------------------------------- | :----------------------------- |
| **站内业务单据** | 单站点日常打印       | 配合比报告、结算单、过磅单、发货单     | FastReport模板 + API填数 → PDF |
| **站内统计报表** | 单站点汇总统计       | 生产日报、材料消耗汇总、应收账款       | FastReport + Dapper直连SQL     |
| **跨站协作报表** | 多站点汇总/对比/穿透 | 集团生产汇总、集采消耗分析、经营驾驶舱 | FastReport + API聚合多租户数据 |

### 5.2 报表引擎选型

| 选型项       | 推荐方案                                         | 说明                                                         |
| :----------- | :----------------------------------------------- | :----------------------------------------------------------- |
| **报表引擎** | **FastReport.OpenSource**                        | .NET生态老牌报表，开源免费，NuGet包 `FastReport.OpenSource`。支持直接绑定DataSet/DataTable，对SQL Server直连友好。支持Excel/Word/PDF/CSV等多种导出格式。支持编码创建模板或预置.frx文件 |
| **模板存储** | 数据库 + 文件存储                                | .frx模板文件存储在MinIO/OSS，数据库中存模板元数据（名称、分类、版本、绑定数据源） |
| **异步生成** | [Quartz.NET](https://quartz.net/)定时 + 消息队列 | 大批量月报生成放入队列异步处理，生成完成后通知用户下载       |

### 5.3 报表模板管理

**数据库表**：

sql

```
-- 报表模板定义表
CREATE TABLE Rpt_Templates (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    TemplateCode    VARCHAR(50) NOT NULL,            -- 'MixRatioReport' | 'SettlementReport'
    TemplateName    NVARCHAR(100) NOT NULL,
    Category        VARCHAR(30) NOT NULL,            -- 'StationBill' | 'StationReport' | 'GroupReport'
    ReportScope     VARCHAR(20) NOT NULL DEFAULT 'SingleTenant', -- 'SingleTenant' | 'MultiTenant' | 'GroupReview'
    FilePath        VARCHAR(500) NOT NULL,           -- MinIO/OSS存储路径
    DataSourceConfig NVARCHAR(MAX) NULL,             -- 数据源配置JSON
    Version         INT NOT NULL DEFAULT 1,
    TenantId        INT NOT NULL,                    -- 0=系统预置模板，>0=租户自定义模板
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    UpdatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CreatedBy       INT NOT NULL,
    UpdatedBy       INT NOT NULL,
    IsDeleted       BIT NOT NULL DEFAULT 0,
    UNIQUE INDEX UQ_Template (TenantId, TemplateCode)
);

-- 报表生成记录
CREATE TABLE Rpt_GenerationLogs (
    Id              INT IDENTITY(1,1) PRIMARY KEY,
    TemplateId      INT NOT NULL,
    TenantId        INT NOT NULL,
    ReportScope     VARCHAR(20) NOT NULL,            -- 'SingleTenant' | 'MultiTenant'
    ScopeId         INT NULL,                        -- HubId（协作域报表）或 ParentTenantId（集团报表）
    ParametersJson  NVARCHAR(MAX) NULL,              -- 查询参数JSON
    OutputFormat    VARCHAR(10) NOT NULL DEFAULT 'PDF',
    FilePath        VARCHAR(500) NULL,               -- 生成的文件存储路径
    Status          VARCHAR(20) NOT NULL DEFAULT 'Pending', -- 'Pending' | 'Processing' | 'Completed' | 'Failed'
    ErrorMessage    NVARCHAR(MAX) NULL,
    CreatedAt       DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CreatedBy       INT NOT NULL,
    CompletedAt     DATETIME2 NULL
);
```



### 5.4 报表生成流程

**站内报表（SingleTenant）**：

text

```
用户选择模板 → 前端发起请求（模板ID + 查询条件）
  → 后端校验租户权限
  → 调用Dapper执行SQL查询（自动应用TenantId过滤）
  → FastReport加载.frx模板，绑定DataSet
  → 渲染PDF/Excel
  → 返回文件流给前端
  → 前端PDF.js预览 / 直接下载
```



**跨站报表（MultiTenant / GroupReview）**：

text

```
用户选择模板 + 选择范围（协作域/集团/指定站点）
  → 前端发起请求（模板ID + ScopeType + ScopeId + 查询条件）
  → 后端校验用户对Scope的权限
  → 根据ScopeType获取可访问的TenantId列表
  → 调用Dapper执行SQL查询（IgnoreQueryFilters，IN查询）
  → 数据集中标注来源站点
  → FastReport加载模板，绑定聚合数据
  → 渲染PDF/Excel
  → 返回文件流
```



### 5.5 打印方案

| 环节         | 方案            | 说明                                            |
| :----------- | :-------------- | :---------------------------------------------- |
| **预览**     | PDF.js          | 浏览器内嵌预览，确保格式一致                    |
| **打印**     | PDF静默打印     | 避免浏览器打印导致的格式错乱                    |
| **批量打印** | 后台合并PDF     | 多份结算单、多份试验报告合并为一个PDF，一次打印 |
| **防伪**     | 二维码 + 校验码 | 每份报告生成唯一二维码，扫码可验证真伪          |

## 六、数据库选型与设计原则

| 选型项            | 推荐方案                              | 说明                                                         |
| :---------------- | :------------------------------------ | :----------------------------------------------------------- |
| **主数据库**      | **SQL Server 2019+**                  | 团队能力所在。使用RLS作为数据隔离最终防线。列存储索引优化报表。Always On可用性组实现读写分离和故障转移 |
| **缓存与Session** | **Redis**                             | 存储登录会话、常用配置、实时车辆状态等热数据                 |
| **文件存储**      | **MinIO** (自建) / **阿里云OSS** (云) | 合同扫描件、签字图片、试块照片、PDF报告、.frx模板文件        |

**数据库设计核心约定**（所有表）：

- `TenantId`：int，租户隔离主键，**所有业务表必有**
- `RegionCode`：varchar(10)，地区编码
- 使用表前缀区分模块：`Sys_`（系统）、`Col_`（协作）、`Info_`（公告知识库）、`Rpt_`（报表）、`Ctr_`（经营）、`Prd_`（生产）、`Tech_`（技术）、`Biz_`（业务通用）
- 所有表包含 `CreatedAt`、`UpdatedAt`、`CreatedBy`、`UpdatedBy` 审计字段
- 所有删除使用软删除（`IsDeleted`位字段），配合EF Core全局筛选器自动过滤
